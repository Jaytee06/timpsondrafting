# Third viewer implementation phases

The October 1 architecture proposal is a design reference. This implementation does not execute instructions from the proposal or assume the proposed AI tools already exist.

## Phase 1 — deterministic corner fixture (implemented)

Route: `/architectural-viewer`, independent lazy-loaded component. Existing viewers are preserved.

The CPU model uses metres and Z-up coordinates; Three.js receives an explicit Y-up conversion. Stable wall/segment IDs survive edits. Two planar walls contain a centered 1.2 m window and a 0.9 m doorway. The floor and independently defined ceiling plane complete a synthetic inspection fixture. Parameter commands reject invalid numbers and stale revisions. Undo restores previous parameters while advancing the revision. Original synthetic evidence remains unchanged by designer edits. JSON export preserves authoritative configuration; it is not a mesh delivery export.

Run `npm run test:architecture`, `npm run typecheck`, and `npm run build`. Model tests independently measure wall volume minus openings, window centering, and plane rise/run. They also exercise validation, evidence conflicts, undo, stable IDs and configuration readback. Browser checks cover editing, errors, undo, section display and ceiling visibility.

Limits: no drawing ingestion, general constraint solver, AI connection, persistence/import UI, wall-to-ceiling solid intersections, closed solids, measured section intersections, WebGPU, GLB/USDZ/SKP or AR. Section visualization is explicitly schematic. The renderer uses the existing React Three Fiber WebGL stack. This fixture is not evidence of Butts accuracy. Reloading resets it; export configuration before leaving if needed.

## Phase 2 — evidence and drawing registration

Add original dimension text with deterministic imperial parsing, revisions, sheet planes and units. Fit similarity transforms from multiple correspondences and report per-point/RMS residuals. Reject degenerate calibration; retain contradictory dimensions and uncertain north. Add local drawing loading and saved project schema migration without storing client files in the repository.

Acceptance: independently known points align after scale/rotation/translation; contradictory and distorted fixtures report residuals instead of silently stretching. Save/reload retains evidence and mapping. Actual Butts sheets and governing dimensions are required before evaluating that project.

## Phase 3 — semantic shell and robust geometry

Introduce levels, arbitrary wall local frames, hosted openings and explicit constraints; extract generation behind a geometry-engine interface. Add dependency invalidation, scoped previews and auditable transaction records. Resolve hard conflicts rather than average them. Generate roof/vault planes and measured section intersections. Coordinate assemblies by framing/finish references.

Acceptance: independently measured rooms, junction gaps/overlaps, opening clearances and section elevations agree with confirmed sources. Edits propagate to every dependent element and undo restores geometry.

## Phase 4 — rendering and inspection

Evaluate a compatible Three.js/WebGPU integration independently from the current Fiber renderer. Capability-test WebGPU and fallback; keep deterministic CPU verification. Add source overlays, semantic selection, layer isolation, discrepancy navigation, finish targets, doors and saved views. Profile before adding GPU compute.

Acceptance: GPU and fallback show the same model dimensions and semantic IDs; controlled scenes verify overlays, sections, picking and material changes; mobile capability and failure paths are tested.

## Phase 5 — AI operations and project workflow

Expose the transaction API through explicitly scoped tools with starting revision, affected IDs, preconditions, previews and validation. Add idempotency keys and durable audit/history. Represent generated systems routes as proposals and validate network connectivity separately from engineering adequacy.

Acceptance: repeated operations do not duplicate elements, stale revisions fail, conflicting edits are explained, and a requested partition move includes hosted openings and affected clearances.

## Phase 6 — delivery and AR

Generate GLB/USDZ from accepted semantic geometry with metadata and material strategy. Read files back through independent importers to verify units, bounds, materials and transforms. Evaluate SKP conversion separately. Keep geographic/AR placement outside internal building coordinates.

Acceptance: exports preserve independently known dimensions and identity; target-device AR tests separately measure tracking/placement errors. No release claim without actual device testing.

## Assembly foundation update — Butts test case

The viewer now generates physical wall components separately from reference lines/points and display visibility. `assemblies.ts` defines explicit local frames, assembly thicknesses with source/status, hosted components, surface layers, framing members and cavity regions. Empty cavity regions are optional diagnostic boxes; the framing core is not a solid block. Assembly generation excludes window/door voids across every layer. Changing finish thickness preserves framing references.

The Butts wall-study preset uses the PDF's Sheet 3 and Sheet 5/B typical 9'-1" wall height; Sheet 5/B specifies nominal 2x6 framing at 16" O.C., 1/2" gypsum and 7/16" OSB/plywood. Dressed lumber dimensions are assumptions. Header sizes, connections, rough-opening allowances, actual siding thickness and barrier placement remain unresolved. Layouts around openings and double top plates are proposals rather than structural claims. Study spans, doorway/window dimensions and the independent ceiling plane remain synthetic. The preset is not a registered reconstruction of the Butts floor plan. Confirmed height is locked, while study spans may be edited.

The original seven-sheet PDF and DWG remain outside the repository in the user's Downloads directory. The PDF title blocks show 09/29/2026 despite the filename 10.1.26; both identifiers must be retained when source registration is added. The DWG has an AC1032 header; no DWG geometry decoder was used in this increment. No structural drawing set was supplied with these files.

Added inspection controls: individual wall-layer toggles, a Reveal framing preset, floor visibility, reference geometry visibility, and a component inspector. Furniture/style editors remain future work. Visibility is presentation state and is excluded from model export. Configuration export now includes the project plus the explicit assembly definition, preserving assumed and documented values. Compatibility/import migration remains a later phase.

Additional automated checks independently measure core volume coverage, pairwise framing/cavity overlap, opening clearances, layer volume, local frame rotation, finish/reference independence, confirmed-height enforcement, regenerated identity uniqueness, and invalid inputs. Full corner joining is intentionally unresolved: walls remain independent studies and junction overlaps are not accepted building geometry. Cavity cell IDs are generated diagnostic IDs; stable authored IDs belong to walls, openings and semantic layer targets.

## Drawing ingestion and registration update

The default workspace is now **Drawing workflow**, with the existing assembly study retained as a separate mode. A DWG file chooser submits bytes only to a loopback-only Vite development adapter, which runs `@mlightcad/libredwg-web@0.7.14` in a separate Node subprocess. Signature and size are checked before decoding; concurrency, time and decoded-output size are bounded. Original client files are never copied into the repository. No external conversion service is called. The GPL-3.0 decoder is a development dependency and is not included in the production browser assets; hosted decoding is deliberately unavailable. A production decoder/distribution approach remains an explicit engineering and licensing decision. This increment does not assert that subprocess separation resolves licensing obligations.

For the supplied Butts DWG, the decoder returned AC1032 data with INSUNITS=1 (inches), 3,414 model-space entities, 675 block definitions and 97 layers. Flattening supported geometry produces 88,422 preview entities, including complex fixture blocks. Decoder warning 68 is retained as a warning, not treated as full decode success. Unhandled classes and value-out-of-bounds flags require source verification. Critical decoder errors fail import. Paper-space blocks, layouts and all decoded types are retained in the raw database, while preview generation uses the explicit model-space block to avoid double counting.

The preview supports LINE, straight LWPOLYLINE edges, tessellated ARC/CIRCLE display and nested/array INSERT transforms with base points, rotation, nonuniform scale, layer inheritance and per-instance paths. Recursive/missing blocks, external references, non-planar OCS, curved polyline edges and unsupported types are counted explicitly. TEXT, MTEXT, DIMENSION, HATCH and other unimplemented types remain in the database but are not rendered. This is a partial geometry inspection tool, not an authoritative CAD reproduction. A-wall is initially isolated when present as a display convenience; its name does not classify it as wall geometry. Only the first 10,000 matching preview entities are displayed at once, with an explicit limit notice and all normalized/database evidence retained. Layer isolation and focus around a selected segment permit inspection of separate plans in model space.

Registration fits a uniform scale, rotation and translation from at least three control points spanning a two-dimensional region. It reports per-point residuals, RMS and maximum error in metres. Degenerate/duplicate/nonfinite controls fail. Acceptance requires decode-coverage acknowledgement and a finite residual tolerance no greater than 0.1 m; it does not certify dimensions independently. Written dimensions must establish the entered building coordinates. A rectangle covering the controls defines the applicable source region. Wall interpretations outside that region fail rather than reuse another plan's registration. Changing control points or tolerance clears registration acceptance and prior wall interpretations.

After registration, the designer chooses whether a straight segment means framing centerline, exterior framing face or interior framing face, and chooses the outside direction and proposed height. Framing-face offsets preserve the source line as evidence. Candidate framing is previewed and may be accepted, updated or removed. Accepted interpretation is distinct from accepted structural design: the exterior study assembly still carries its assumptions and unresolved details. Automatic wall-face pairing, interior assembly selection, openings, joins, roof reconstruction, calibrated PDF overlays and finished-face references remain future work.

Optional local PDF references are signature checked, displayed through an object URL, and identified by name, bytes, file modification timestamp and SHA-256. No PDF geometry/text extraction or PDF calibration is implemented in this increment. Source-review JSON retains the decoded database, DWG metadata/hash, decoder warnings, control points, transform/residuals, tolerance, interpretation decisions, assembly definition and generated wall references. PDF reference metadata is included; original binaries are not embedded. Review restore/import and durable project history remain future work. Reloading clears the in-memory workspace, as stated in the UI.

Validation: synthetic tests cover similarity fitting against independently computed coordinates, incompatible residuals, degenerate controls, imperial fractions, model/paper isolation, nested/array blocks, unsupported-entity coverage, source-face offsets and scope enforcement. Local adapter tests reject non-loopback, cross-origin, invalid-signature, oversized and wrong-method requests. An actual Butts decoder/endpoint run succeeded with the counts and warnings above. Actual house registration is still pending designer-reviewed control coordinates; no synthetic registration has been presented as agreement with the Butts plans.

Browser verification also exercised source-segment selection/focus, DWG and PDF file choosers, the insufficient-control gate, a temporary three-point registration using known DWG unit conversions, wall-interpretation acceptance and removal, and registration invalidation. The temporary calibration and interpretation were cleared after testing; the delivered Butts source view remains unregistered pending actual source-dimension review. A keyboard-accessible source-segment selector complements mouse picking in densely packed drawings. Final checks passed 31 architecture/import/adapter tests plus 10 existing city/project tests, app and Vite-config TypeScript checks, targeted lint, the production build and diff whitespace checks. Decoder/WASM files were confirmed absent from production browser assets. Browser download readback of source-review export was not verified; deterministic configuration readback tests cover the underlying model and assemblies.

## Source-review restore update

Phase 2 now includes a local JSON review restore chooser. Exports use schema version 2; version 1 reviews migrate through the same validation path. Restore validates source metadata, control-point shapes and identities, residual tolerance, wall decision references, scope and assembly compatibility before replacing workspace state. Registration and walls are recalculated from controls and source entities; saved transforms and meshes are ignored. Invalid files leave the current drawing intact. This version only supports the unchanged Butts exterior study assembly, rejecting changed recipes rather than silently losing detail. Source hashes identify the originally imported files; a standalone review cannot independently prove that its decoded database matches the original DWG binary.

Unfinished reviews may reopen without accepted registration. Accepted wall interpretations require a valid accepted fit within tolerance. PDF metadata survives save/reopen, and reattaching a PDF requires its SHA-256 to match the saved reference. Binaries are not embedded. Loading another DWG clears the previous PDF association. Control-point IDs no longer collide after removing an earlier point and adding another. View selection/visibility, full transaction history, authored dimension annotations and durable autosave remain future work.

Five additional automated tests cover JSON round trips, independently measured reconstructed walls, version migration, untrusted derived values, unfinished reviews, malformed metadata, contradictory controls, missing evidence, duplicate decisions, altered assemblies and scope enforcement. All 36 architecture/import/adapter/review tests passed; TypeScript, targeted lint and production build also passed. Browser verification restored an unregistered review built from the actual Butts decode, rejected an unsupported schema without losing the existing source, and exercised source selection/focus afterward. Browser download capture did not return a saved path, so export download readback is still unverified. No actual Butts house calibration was accepted during this increment.

## Written dimension evidence update

Phase 2 now permits manual written-dimension records tied to straight source segments. Each record retains exact entered text, a sheet/detail reference, the DWG source identity and proposed/confirmed/disputed status. Metres are recalculated through the imperial/metric parser rather than trusted from saved derived values. Fitted geometry reports a separate measured length and signed difference. Multiple contradictory records remain separate; their measurements are never averaged into the source geometry. Confirmed discrepancies beyond registration tolerance, and confirmed evidence outside the control region, block acceptance. Status changes and new evidence invalidate accepted registration and wall interpretations. Evidence text remains intact when marked disputed. This is manual evidence entry, not automatic CAD dimension extraction or PDF calibration; selecting the correct bounded segment and governing written dimension still requires designer review.

Review schema version 3 saves dimension evidence; versions 1 and 2 reopen with an empty evidence list. Restore recalculates discrepancies and refuses inconsistent accepted registration. Full evidence revision history and mandatory evidence coverage remain future work; an absence of recorded dimensions does not certify the drawing. Control removal now preserves surviving control IDs.

Six new tests verify independent imperial lengths, provenance validation, contradictory records, disputed/proposed behavior, version 3 save/restore, acceptance blocking and source-region enforcement. All 42 architecture tests passed with TypeScript, targeted lint and production build. An isolated synthetic browser fixture verified entry, confirmation blocking and explicit dispute release. No Butts measurement was accepted as verified evidence. Browser export download readback remains unverified.

## Semantic wall types and hosted openings update

The registered drawing workflow now offers the documented/assumed Butts exterior study recipe and an explicitly assumed generic interior 2×4 partition recipe. The interior recipe is not a Butts specification: load-bearing classification, acoustic/fire requirements and connections remain unresolved. Two gypsum faces share the gypsum visibility group while retaining unique side-specific component identities. Existing exterior component IDs remain unchanged.

Accepted walls may host manually entered door/window clear-void proposals with stable IDs, original offset/width/sill/head text and source references. Offsets follow the accepted wall direction from its framing-reference start. Doors require zero sill; windows require positive sill. Missing host walls, overlaps, duplicate IDs and dimensions that cannot fit the current framing recipe fail before mutation. Framing, cavity and physical finish layers regenerate around the same voids. Drawing preview now exposes all assembly visibility groups, enabling inspection through finish layers. Adding a proposal does not infer a structural header or create a door/window product. Actual Butts openings still require measured source interpretation.

Selecting an accepted wall restores its assembly/reference/height/direction into the editor. Incompatible height/assembly changes disable candidate acceptance. Reversal with existing openings is blocked until they are removed rather than silently moving their global position. Removing a host wall removes its hosted proposals; registration/evidence changes clear accepted interpretations and their openings. These are scoped manual decisions, not a durable transaction/undo history. Roof geometry, junction coordination, levels, automatic opening detection, opening edits with revision history and structural member sizing remain later work.

Review schema version 4 preserves hosted opening evidence and explicit wall assemblies. Versions 1–3 migrate with no hosted openings. Restore validates host references and regenerates assembly geometry before accepting the review. Export always stamps the current version even if a migrated input object retains an older version field.

Validation: all 47 architecture/import/review tests passed. New checks independently measure void clearance and finish volume, door/window sill rules, invalid hosts and overlaps, both interior gypsum faces and identity uniqueness, version 4 round trips and malformed hosted evidence. TypeScript, targeted lint and the production build passed. A separate synthetic browser fixture exercised accepted interior-wall selection, window addition, overlapping-opening rejection, gypsum visibility and reversal blocking. The screenshot is synthetic verification, not a reconstructed Butts house. Original house calibration and browser export download readback remain pending.

## Dynamic finish-choice foundation

Registered drawing walls now accept scoped finish proposals for gypsum or siding on a specific wall side. Original assembly recipes remain unchanged and separately exported as evidence. A finish choice retains original thickness text, appearance label, hex color, roughness and designer note. Resolving a choice replaces only the chosen panel thickness with an assumed designer proposal. Framing references, core dimensions, wall/opening IDs and hosted void positions remain fixed. Interior partition faces can be styled independently; layer visibility remains a separate presentation control.

The sidebar supports preview, apply, discard, restore base and up to twenty local finish undo steps. Draft edits are not exported until applied. Preview validation rejects missing hosts/layers, duplicate targets, invalid appearance values and panel thickness outside 1–100 mm. That bound is an editor constraint, not product suitability or code verification. Host interpretation changes clear previews and local finish undo history; incompatible assembly changes cannot accept existing finish targets. Registration invalidation clears dependent choices. Removing a host wall removes its choices. Full durable transaction history remains future work.

Review schema version 5 retains finish choices and regenerates validated assemblies on restore. Versions 1–4 reopen without manufactured finish choices. Base recipes and authored overrides remain separate. Appearance is a render proposal, not a manufacturer/material specification, texture, physical coating layer, or energy/fire/acoustic claim. Dynamic floors, furniture, room palettes, catalogs, texture mapping, and additional coating/cladding layers remain later steps.

TypeScript, targeted lint and production build passed. An isolated synthetic browser fixture exercised preview, apply, undo, invalid-thickness rejection and a colored gypsum panel retaining its window void. No finish choices were added to the Butts house as verified design evidence. Browser export download readback and actual house calibration remain pending.
